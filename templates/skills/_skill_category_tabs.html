{% load i18n lumen %} {% comment %} One tab per skill category, over a single panel — the categories that this profile actually has skills in, which is the same set the page showed as a grid of cards before. Tab state lives in the URL fragment (`#category-`), written with `replaceState` so it neither stacks history entries nor makes the browser jump to an element. That is also what lets the add/edit/delete views send you back to the category you just worked in — see `skills.views.skills_url`. The fragment deliberately matches no element id (panels are `panel-category-`) so restoring it on load cannot scroll the page. Keyboard behaviour follows the WAI-ARIA tabs pattern: one tab stop for the whole strip, arrow keys move between tabs, Home/End jump to the ends. Each panel is a data table. The one search box above the strip filters every category at once (you rarely know which one a skill was filed under), and each tab's count follows the matches — see static/js/data-table.js. {% endcomment %} {% if grouped %}
